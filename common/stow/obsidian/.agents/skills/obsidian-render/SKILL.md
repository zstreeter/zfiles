# /obsidian-render

Open Obsidian **at a specific file**, or render a vault note into a paper. Both
run through zfiles scripts on `$PATH` — never reimplement their logic here.

```
obsidian-open [-v <vault>] [<file>]   open Obsidian at a note
obsidian-vault path|name|list|config  resolve vault locations
obsidian-render <note.md> [--to ...]  note -> PDF / LaTeX / HTML
```

Source: `~/zfiles/common/stow/scripts/.local/bin/`.

## Opening a note

```bash
obsidian-open "Sparse Correction Vectors for Spectral Functions.md"
obsidian-open -v Research notes/method.md
obsidian-open ~/research/gf/notes/method.md   # absolute path infers its vault
obsidian-open                                  # just bring up the vault
```

The `.md` extension is optional. With no argument it opens the default vault:
`$ZFILES_OBSIDIAN_VAULT`, else the vault Obsidian currently has open, else the
most recently used, else a `~/research/*` vault.

**After `/obsidian-note` writes a note, open it** — that's the whole workflow:
conversation in the terminal, rendered math in Obsidian beside it.

### When it doesn't land on the note

`obsidian://` URIs address a vault **by name**, and Obsidian only knows names
for vaults it has opened at least once. A vault it has never opened makes the
URI fall back to the vault switcher. The fix is one-time and manual: open the
vault in Obsidian (File → Open vault), after which the URI works forever.

Obsidian is single-instance, so this switches the existing window rather than
starting a second one. That is intended.

## Rendering to a paper

**Quarto reads Obsidian notes directly.** There is no conversion step and no
intermediate file. In a vault scaffolded by `new-research-project`:

```bash
quarto render notes/method.md --to typst   # paper: PDF via Typst, no TeX needed
quarto render notes/method.md --to pdf     # the same through lualatex, when a venue needs it
quarto render notes/method.md --to latex   # .tex for arXiv or a journal
quarto preview notes/method.md             # live reload while editing in Obsidian
```

`quarto preview` is the one worth reaching for: edit the note in Obsidian, see
the typeset PDF-style HTML update as you type.

`obsidian-render` still exists, but it is now only a convenience wrapper — it
remembers the flags and handles a note that lives **outside** any vault. Inside
a vault, prefer `quarto` directly.

### What makes this work

The vault's `_quarto.yml` carries two settings:

```yaml
from: markdown+wikilinks_title_after_pipe+mark
filters:
  - at: pre-ast
    path: _extensions/obsidian/obsidian.lua
```

Pandoc handles `[[Note]]`, `![[img.png]]` and `==highlight==` natively; the
`obsidian` Lua filter (`_extensions/obsidian/obsidian.lua`) adds the four things
Pandoc has no concept of — `[[@citekey]]` citations, `![[Note#Section]]`
transclusion, `> [!callout]` blocks, and `%%comments%%`.

Because the filter runs on the parsed syntax tree rather than on text, math is
already a `Math` node by the time any rule sees it and cannot be corrupted. Keep
it that way: **never "fix" Obsidian syntax with a regex over the note.**

If something renders wrong, see the `quarto` and `pandoc` skills — the failure
is almost always filter ordering or a missing reader extension, both of which
are diagnosable from the generated `.tex` (`keep-tex: true` is already set).

`[[@citekey]]` becomes a real citation resolved against the vault's
`references.bib`. Keep writing citations that way in notes; see the `zotero`
skill for where that file comes from.

## Constraints

- **Never write into `.obsidian/` or `obsidian.json`.** That file is Obsidian's
  vault registry and the app owns it; `obsidian-vault` only reads it.
- `references.bib` is generated by Better BibTeX. Read-only, never hand-edit.
- The default vault on this machine lives in a corporate OneDrive folder and
  syncs. No secrets, credentials, or proprietary source in a note.
- If a script is missing from `$PATH`, the fix is `cd ~/zfiles && ./bootstrap.sh`
  (or stow the `scripts` package) — don't inline a replacement.
